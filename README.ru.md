# @shelamkoff/color-picker

[![версия npm](https://img.shields.io/npm/v/%40shelamkoff%2Fcolor-picker)](https://www.npmjs.com/package/@shelamkoff/color-picker)
[![Онлайн-демо](https://img.shields.io/badge/demo-live-4357b4)](https://shelamkoff.github.io/color-picker/)
[![Лицензия MIT](https://img.shields.io/badge/license-MIT-2ea44f)](./LICENSE)

Доступный и независимый от фреймворков компонент выбора цвета с необязательной поддержкой системной пипетки, чистыми функциями работы с цветом и вводом HEX, RGB, HSL, именованных цветов и OKLCH. Поставляется как ESM-пакет для современных браузеров.

[Онлайн-демо](https://shelamkoff.github.io/color-picker/) · [npm](https://www.npmjs.com/package/@shelamkoff/color-picker) · [English README](./README.md)

## Возможности

- Управление насыщенностью, яркостью, тоном, прозрачностью и форматом результата.
- Указатель, сенсорный ввод и клавиатура с необязательной поддержкой системной пипетки.
- Чистые функции разбора, форматирования и преобразования цвета в отдельной точке входа.
- Независимый от фреймворков жизненный цикл, обработчики и явное освобождение ресурсов.

## Установка

```bash
npm install @shelamkoff/color-picker
```

Один раз подключите таблицу стилей:

```js
import '@shelamkoff/color-picker/styles.css'
```

Если приложение создаёт `<link>` во время выполнения, используйте экспорт `colorPickerStylesUrl`.

## Быстрый старт

Добавьте контейнер для встроенного отображения:

```html
<div id="color-picker-mount"></div>
<style>
  #color-picker-mount > .oe-color-dropdown {
    position: static;
    transform: none;
  }
</style>
```

```js
import { ColorPicker } from '@shelamkoff/color-picker'
import '@shelamkoff/color-picker/styles.css'

const picker = new ColorPicker({
  onChange(color) {
    preview.style.color = color
  },
  onApply(color) {
    saveColor(color)
    picker.close()
  },
  onRemove() {
    clearColor()
  },
  showRemove: true,
})

document.querySelector('#color-picker-mount').append(picker.element)
picker.open('#3366ffcc')
```

После создания компонент скрыт. Показывайте его методом `open()`, а при уничтожении владеющего экрана вызывайте `destroy()`.

По умолчанию таблица стилей размещает компонент как абсолютную панель под позиционированным родителем. Пример выше меняет только размещение: не переопределяйте `display`, поскольку видимостью управляют `open()` и `close()`. Для выпадающей панели добавьте компонент в родителя с `position: relative`; приложение отвечает за размещение, закрытие по внешнему клику, начальный фокус и его восстановление.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `onChange` | `(color: string) => void` | пустая функция | Получает CSS-цвет после каждого завершённого изменения элемента управления. |
| `onApply` | `(color: string) => void` | пустая функция | Получает корректный цвет после нажатия Apply или Enter. |
| `onRemove` | `() => void` | пустая функция | Вызывается после нажатия кнопки удаления цвета. |
| `onFormatChange` | `(color: string, format: ColorFormat) => void` | пустая функция | Вызывается при смене формата вывода. |
| `showRemove` | `boolean` | `true` | Показывает или скрывает действие удаления. |

## API экземпляра

| Член API | Описание |
| --- | --- |
| `element` | Корневой `HTMLElement`, принадлежащий компоненту. |
| `open(color, alpha?)` | Проверяет цвет и прозрачность, завершает прежние взаимодействия, синхронизирует элементы управления и показывает компонент. |
| `close()` | Скрывает компонент, завершает перетаскивание и отменяет ожидающий запрос системной пипетки. |
| `destroy()` | Удаляет созданный DOM и обработчики. Повторный вызов безопасен; после уничтожения `open()` выбрасывает ошибку. |

`open()` принимает перечисленные ниже форматы. Некорректный цвет или неконечная прозрачность приводят к исключению без изменения текущего состояния. Отдельное конечное значение прозрачности ограничивается диапазоном `0..1`.

## Функции работы с цветом

Функции доступны из корня пакета и из облегчённой точки входа `color-math`:

```js
import {
  parseColorInput,
  formatColor,
  hsvToRgb,
} from '@shelamkoff/color-picker/color-math'

const hsva = parseColorInput('oklch(65% .15 250 / 80%)')
if (hsva) {
  const rgb = hsvToRgb(hsva.h, hsva.s, hsva.v)
  const css = formatColor(hsva.h, hsva.s, hsva.v, hsva.a, 'RGB')
  console.log(rgb, css)
}
```

Пакет экспортирует `COLOR_FORMATS`, `ColorFormat`, `hsvToHex`, `rgbToHsv`, `hexToHsv`, `hsvToRgb`, `hsvToHsl`, `formatColor`, `roundAlpha`, `parseRgbCss` и `parseColorInput`.

`parseColorInput()` принимает следующие самостоятельные значения цвета и возвращает HSVA на основе sRGB:

| Ввод | Примеры и правила |
| --- | --- |
| HEX | `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`; в короткой записи удваивается каждая цифра, включая alpha. |
| RGB(A) | `rgb(255, 0, 128)`, `rgba(100%, 0%, 50%, .5)`, `rgb(255 0 50% / 80%)`. Числовые каналы могут быть дробными. Современная запись допускает сочетание чисел и процентов; в записи с запятыми все три канала используют один вид значений. |
| HSL(A) | `hsl(220, 100%, 60%)`, `hsl(.5turn 100% 50% / 25%)`. В современной записи насыщенность и светлота принимают проценты или числа по той же шкале `0..100`; запись с запятыми требует процентов. |
| Именованные цвета | Все 148 стандартных имён CSS, включая синонимы `gray`/`grey` и `rebeccapurple`. `transparent` означает прозрачный чёрный. |
| OKLCH | `oklch(65% .15 250 / 80%)`. Светлота `100%` соответствует `1`, цветность `100%` — `.4`. Цветность неотрицательная, без фиксированного верхнего предела. |

Alpha принимает число в `0..1` или процент в `0..100%`. Тон HSL и OKLCH задаётся в градусах без суффикса либо с `deg`, `grad`, `rad`, `turn` и нормализуется по кругу. Поддерживаются знак числа и экспоненциальная запись. В современной записи `none` преобразуется в ноль при разборе самостоятельного цвета. Регистр и пробелы по краям строки не учитываются. Смешивать запятые с синтаксисом пробелов и `/` нельзя.

OKLCH преобразуется во внутреннюю модель пикера sRGB/HSV. Цвета вне охвата sRGB приводятся к нему алгоритмом двоичного поиска с local MINDE из CSS Color 4; цвета внутри охвата преобразуются напрямую. Исходные координаты OKLCH не сохраняются: компонент остаётся редактором sRGB с форматами вывода HEX, RGB и HSL. Подробнее: [синтаксис CSS Color 4](https://www.w3.org/TR/css-color-4/) и [алгоритм приведения к охвату](https://www.w3.org/TR/css-color-4/#binsearch).

Сохраняется строгая проверка диапазонов API: каналы RGB — `0..255` или `0..100%`, насыщенность и светлота HSL — `0..100`, светлота OKLCH — `0..1`, alpha — `0..1`. Некорректный, бесконечный, неподдерживаемый или выходящий за диапазон ввод возвращает `null`, а не ограничивается диапазоном, как в CSS браузера. Выражения, которым нужен контекст, например `currentColor`, `var()`, `calc()` и относительные цвета, не вычисляются.

`parseRgbCss()` — отдельная совместимая вспомогательная функция для современной записи RGB(A) и записи с запятыми, включая проценты. Она ограничивает каналы и alpha допустимым диапазоном, а при некорректном или неподдерживаемом вводе возвращает `{ hex: '#ffffff', alpha: 1 }`. Если нужно отличать ошибку от белого цвета, используйте `parseColorInput()`. `hexToHsv()` принимает только шестизначный hex с необязательным `#` и выбрасывает исключение при ошибке.

`hsvToHsl()` и форматирование HSL округляют тон, насыщенность и светлоту до целых чисел; форматирование RGB/HSL и callbacks округляют alpha до двух десятичных знаков. Формат HEX использует восьмибитный канал alpha. Поэтому преобразование в строку может терять точность. Переключение формата в пикере с применением неизменённого поля сохраняет внутренний цвет, не разбирая округлённый текст заново.

## Взаимодействие и жизненный цикл

- Поля насыщенности и яркости, тона и прозрачности поддерживают указатель, сенсорный ввод и клавиатуру.
- Кнопка системной пипетки появляется только при наличии соответствующего API браузера. Повторный `open()`, `close()` и `destroy()` отменяют ожидающий выбор и игнорируют устаревшие результаты.
- Escape закрывает компонент с любого элемента управления. Некорректный текст отмечается `aria-invalid` и не применяется. Enter во время композиционного ввода IME не применяет цвет.
- Компонент не сохраняет цвет самостоятельно. За интеграцию отвечают переданные приложением обработчики `onApply`, `onChange` и `onRemove`.
- CSS-переменные с префиксом `--oe-` позволяют переопределить резервную тему компонента.

## Проверки при разработке

```bash
npm ci
npm test
npm run test:package
npx playwright install chromium
npm run test:browser
```

`npm test` запускает проверки преобразования и разбора цветов, регрессии локального демо-сервера, а также сценарии жизненного цикла и ввода в Happy DOM. В DOM-тестах геометрия задана явно: они не проверяют отрисовку и нативный захват указателя.

`test:package` собирает и устанавливает настоящий tarball во временный проект, проверяет ESM-импорты без DOM, экспорт таблицы стилей и публичные типы в строгих режимах NodeNext и Bundler.

`test:browser` запускает локальный сервер и проверяет общие сценарии жизненного цикла, настоящий ввод мышью, клавиатуру и размещение демо в Chromium. Дополнительно он сравнивает 240 цветов с независимым результатом браузерного sRGB Canvas: все 148 имён, OKLCH внутри охвата и новые варианты синтаксиса. Неподдерживаемые браузером варианты перечисляются отдельно; отсутствие достаточной проверки OKLCH завершает тест ошибкой. Для другого установленного браузера Playwright задайте `COLOR_PICKER_BROWSER=firefox` или `webkit`. Переменная `COLOR_PICKER_BROWSER_EXECUTABLE_PATH` позволяет указать существующий исполняемый файл браузера. Ошибка запуска браузера завершает проверку неуспешно и не считается пройденным тестом.

Перед релизом выполняйте `npm run check`, объединяющий три проверки. Нативный интерфейс EyeDropper и работу вспомогательных технологий дополнительно проверяйте вручную на целевых платформах.
